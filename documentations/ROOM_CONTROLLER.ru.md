# Room Controller

Краткая документация для маппера по установке `Room Controller` в дормы.

## Что делает контроллер

`Room Controller` это панель управления одной приватной комнатой.

Сейчас она умеет:

- назначать владельца комнаты по первой вставленной ID-карте
- менять имя комнаты
- менять описание комнаты
- менять иконку комнаты
- переключать режимы `Open / Guests Only / Closed`
- переключать видимость комнаты
- скрывать или показывать имена гостей
- добавлять и удалять trusted guests
- передавать владение через вставленную ID-карту
- реально ограничивать вход через дверь комнаты
- блокировать обычным ghosts наблюдение за происходящим в комнате, если комната не `Open`

## Что ставить на карту

Базовый объект:

```dm
/obj/machinery/room_controller
```

Обычно удобнее ставить directional-вариант:

```dm
/obj/machinery/room_controller/directional/north
/obj/machinery/room_controller/directional/south
/obj/machinery/room_controller/directional/east
/obj/machinery/room_controller/directional/west
```

Directional-варианты уже имеют пиксельный сдвиг для настенной установки.

## Что обязательно настроить

Нужно задать `room_number`.

Пример:

```dm
/obj/machinery/room_controller/directional/west{
	room_number = 101
}
```

Без `room_number` панель всё равно будет существовать, но на экране покажет ошибку вместо нормального номера.

## Что обязательно для нормальной работы

Для каждой дормы нужна отдельная `area`.

Это обязательное условие, потому что контроллер:

- определяет свою комнату по `area`
- ищет связанную дверь по `area`
- применяет ghost-privacy по `area`

Если несколько дорм находятся в одной общей `area`, механика будет работать неправильно:

- одна панель может зацепить не ту дверь
- приватность будет действовать сразу на несколько комнат
- гости и владелец будут проверяться не для той комнаты, для которой ожидалось

## Как должна быть собрана дорма

Минимально правильная схема:

1. У комнаты есть отдельная `area`.
2. `Room Controller` стоит внутри этой `area`.
3. Входная дверь комнаты относится к этой же `area`.
4. У контроллера задан уникальный `room_number`.

Лучший вариант:

- вся внутренняя часть дормы и её входной airlock находятся в одной `area`

Допустимый запасной вариант:

- дверь стоит на соседнем пороге, но вплотную к комнате

Контроллер умеет попытаться подобрать такую дверь автоматически, но это fallback, а не основной рекомендованный способ.

## Как работает доступ

После назначения владельца режимы работают так:

- `Open`: дверь открывается для всех
- `Guests Only`: дверь открывается только владельцу и trusted guests
- `Closed`: дверь открывается только владельцу

Trusted guests проверяются по имени персонажа.

## Как работает ghost privacy

Когда комната не `Open`, модуль делает две вещи:

- не даёт обычным ghosts наблюдать живых внутри комнаты через `observe`
- выталкивает обычных ghosts из комнаты, если они туда залетают

Это не относится к админским ghost-привилегиям.

## Что игрок делает в игре

1. Вставляет ID-карту в панель.
2. Первая ID назначает владельца комнаты.
3. Владелец настраивает имя, описание, иконку и статус доступа.
4. При необходимости владелец добавляет trusted guests.
5. При необходимости владелец вставляет другую ID-карту и передаёт комнату новому владельцу.

## Быстрая проверка после маппинга

Проверь в игре:

1. Панель открывается.
2. На панели отображается правильный `room_number`.
3. После вставки ID назначается владелец.
4. В режиме `Closed` чужой игрок не может открыть дверь.
5. В режиме `Guests Only` trusted guest может войти, а посторонний не может.
6. В режиме `Open` дверь снова пускает всех.
7. Ghost не может спокойно смотреть комнату, если она не `Open`.

## Самое короткое правило для маппера

Если без подробностей, то нужно сделать так:

- выделить каждой дорме отдельную `area`
- поставить внутрь `/obj/machinery/room_controller/directional/...`
- задать `room_number`
- убедиться, что входная дверь этой дормы относится к той же `area`

Этого достаточно, чтобы контроллер заработал как задумано.
